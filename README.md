# OneLaser · 工作与成果

[简体中文](README.md) · [English](README.en.md)

GitHub Pages 默认是面向 1–2 个部门、10–30 人试点方案的浏览器演示，员工、任务、业务指标与验收记录均为虚构数据，演示日期固定为 2026-10-27。仓库同时提供独立的企业真实模式，由同源后台执行登录、授权和业务持久化。

[在线演示](https://yonge6.github.io/onelaser-workos/) · [GitHub 仓库](https://github.com/Yonge6/onelaser-workos)

## 中英双语与日间 / 夜间主题

首页和工作空间顶栏提供 **中 / EN** 语言按钮与 **太阳 / 月亮** 主题图标 切换。选择保存在当前浏览器，下次打开会继续使用；首次主题跟随系统偏好。切换语言会更新标题、表单提示、任务样本、目标、验收说明与集成状态，保持同一份业务数据与当前视图。用户自己录入的任务、材料和评价原样保留，不做自动翻译。导出记录中的预设文案与元信息使用当前语言，业务记录在浏览器中仍只保存一份。

品牌区域使用原始英文 OneLaser SVG 标志与固定英文 `Work OS`，按主题选择黑字或白字版本，保留完整比例。深色主题覆盖列表、看板、表单、抽屉、弹窗、提醒和空态，不使用全局反色。

## 企业真实模式与 API 对接

同一份前端提供两个明确分离的模式：GitHub Pages 默认 `demo`，只展示虚构样本；企业部署使用 `live`，所有业务记录从同源后台读取和保存。真实模式没有任意身份切换，不读取或导入演示 `localStorage`，也不会在服务不可用时自动退回虚构数据。

生产服务需要在 `/runtime-config.js` 返回以下公开配置，并设置 `Cache-Control: no-store`：

```js
window.WORKOS_CONFIG = Object.freeze({ mode: 'live', apiBase: '/api' });
```

此配置没有密钥。`apiBase` 必须与页面同源；建议静态文件放在站点根目录，`/api/*` 代理到后台对应路由并去掉 `/api` 前缀。GitHub 仓库中的 `dist/runtime-config.js` 保持演示默认，不应向公开 Pages 填入企业凭证。

真实模式先检查 `/capabilities` 与 `/me`，未登录只展示钉钉登录页。登录跳转 `/api/auth/dingtalk/start`，由后台处理 OAuth 并设置 HttpOnly、Secure、SameSite Cookie。前端不读取或存储会话令牌。写请求先读取 `/api/auth/csrf` 并携带 `X-CSRF-Token`；401 会立即清除内存中的员工记录，409 要求重新读取当前版本后人工确认。

已实现的 API 界面包括任务创建与筛选、OKR 和 KR 创建、实际值核验、成果版本提交、指定负责人验收、当前版本 Grok 分析、提醒预览和负责人显式发送。AI 显示当前提交的来源引用、缺失证据和不确定项；通知只将钉钉受理成功显示为“已提交发送队列”，不宣称送达。具体是否可调用由后台配置和实际响应决定。

`capabilities.aiReviewMode` 选择同步 `api` 或异步 `bot` 路径。Bot 的提交、等待领取、运行、完成、失败、提交待核实、过期和被替代分别显示；受理不等于分析完成。任务详情只展示当前成果版本的分析，旧版本任务单独标注。状态以 2 / 4 / 8 / 15 秒退避读取，约两分钟后停止并提供手动刷新；关闭详情、切换任务或会话失效会取消读取。失败、过期或提交不确定时需明确重试，不自动重放写请求；提交不确定时，用户须确认原任务可能仍运行并重复消耗 Bot 额度。已有 Bot 额度、模型 API 计费和实际服务可用性由对应账户决定，界面不承诺免费或无限调用。AI 结果继续由负责人实际核验。

`dist/preferences.js` 在样式加载前恢复语言和主题，脚本不需要 CSP `unsafe-inline`。`dist/api-client.js` 负责 Cookie、CSRF、语言和结构化错误；`dist/live-app.js` 负责真实工作空间。以下本地测试覆盖同源约束、CSRF、会话失效、未登录数据隔离、服务端记录渲染以及演示/真实模式隔离：

```sh
node --test test/*.test.mjs
```

这些测试包含模拟 HTTP 响应，不代替企业钉钉登录、真实模型及消息投递的线上验收。

## 本地运行

不需要依赖安装或构建：

```sh
git clone https://github.com/Yonge6/onelaser-workos.git
cd onelaser-workos
python3 -m http.server 8867 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8867`。

## 可以体验的流程

1. 首页选择“任务”或“OKR”，切换演示身份体验本人或部门范围。
2. 任务列表/看板、关键词与状态筛选、新建任务、关联关键结果。
3. 员工提交成果标题、说明、可选 HTTPS 链接与标准覆盖自述。
4. 本地“演示评审”检查材料字段；显示材料缺口和未验证范围，不调用模型、不生成实际成果质量评分。
5. 负责人实际核对材料，填写 0–100 的人工质量分与意见，验收通过或退回补充。
6. 提交新版本时，旧的检查和验收结果同时失效；事件记录保留历史。
7. OKR 按业务指标的基线、当前值、目标值计算进度，与任务速度和质量分分开。
8. 查看已人审的绩效参考指标及每人样本数。没有样本显示“—”；样本门槛与覆盖率需按岗位校准；当前原型不计算综合执行分。
9. 查看钉钉登录、通讯录、通知、独立 AI 模型接口接入说明。提醒只预览草稿，不发送。
10. 导出当前可见范围的演示数据，或经确认后恢复初始样本。

## 演示模式实现与限制

- `dist/index.html`、`styles.css`、`i18n.js`、`app.js` 为无外部依赖的静态页面，支持移动端与键盘操作。`i18n.js` 集中维护中英文字典、动态文案模板和固定样本翻译；界面翻译不会改变组织键、任务 ID、表单值或权限逻辑。
- 浏览器 `localStorage` 保存演示业务记录，键为 `onelaser-workos-demo-v4`；同一来源的浏览器共享这些演示记录。
- 切换身份仅模拟界面范围，**不是认证或安全边界**。生产版须在服务端重新实施登录、组织成员关系、角色授权与对象级数据权限。
- 当前界面范围：员工只看本人任务；负责人只看本部门任务。公司目标属于演示公开目标，个人目标按可见范围筛选。负责人不能验收本人任务；生产版需为这类任务指定上级或其他授权验收人。
- 提交内容经过 HTML 转义，成果链接只允许不含用户名/密码的 HTTPS URL。页面不读取成果链接、不上传附件。
- 演示模式没有数据库、真实员工登录、多人同步、文件存储、模型调用、通知发送、定时任务或企业接口连接。企业真实模式通过同源后台提供已配置的能力，不使用演示数据。
- 现有 Grok Bot 的自动化接口能力未核实；Bot 和 xAI 模型 API 均未接入。任何服务端配置名称只作接入说明，不在浏览器收集密钥。
- 原型不接收真实薪资，不生成员工去留结论，不自动调整薪资。绩效指标需要负责人复核，且必须结合岗位、工作日历、依赖与批准的变更。
- 演示材料规则只看标题、文本长度与员工自述覆盖；字段齐全不等于真实成果符合标准，也不代表质量分。

## 演示口径

- KR 进度：`(当前值 - 基线) / (目标值 - 基线)`，展示值截断到 0–100%；本原型仅放置增长型指标。
- 人工成果质量 Q：当前版本已经验收任务的人工质量评分平均值。
- 按期交付 T：已经验收任务中，成果提交时间不晚于有效截止日 18:00 的比例。演示提交与事件时间使用同一个固定业务演示时钟，避免显示时间与计算依据分离。导出元信息另记录实际导出时间。
- 计划一致 P：已经验收任务中，负责人确认成果与确认范围一致的比例。
- 响应约定 R：有工作时间响应数据的已验收任务中，在 4 个工作小时内响应的比例；原型不采集真实员工响应行为。
- 待确认权重 Q 50% / T 20% / P 20% / R 10% 仅为方案草案；当前不计算个人综合执行分或跨岗位排名。

后续正式开发应按项目 `spec/` 中的服务端规则与交付方案实施，并完成真实登录、权限、文件与证据读取、审计、模型输出强校验及试点验收。

## GitHub Pages 发布

推送 `main` 分支的网页修改后，GitHub Actions 自动部署 `dist/`。也可以在 Actions 中手动运行 Deploy GitHub Pages。页面公开可访问，仅用于虚构数据的产品流程演示；真实员工系统需要独立后端、身份认证和服务端权限。

网页脚本和样式带有同一版本查询参数。后续同时修改语言、脚本或样式时应同步更新版本，避免浏览器缓存将不同版本混用。

## 后台 API

[后台 API 源码](https://github.com/Yonge6/onelaser-workos-api)单独维护。GitHub Pages 默认使用浏览器本地演示数据；企业真实模式通过同源 `/api` 调用后台。钉钉、模型和通知的真实可用性以服务端配置与线上验收为准。
