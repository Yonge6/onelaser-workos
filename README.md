# OneLaser · 工作与成果（交互原型）

这是面向 1–2 个部门、10–30 人试点方案的浏览器交互原型。全部员工、任务、业务指标与验收记录均为虚构数据；当前固定业务演示日期为 2026-10-27。

[在线演示](https://yonge6.github.io/onelaser-workos/) · [GitHub 仓库](https://github.com/Yonge6/onelaser-workos)

## 本地运行

不需要依赖安装或构建：

```sh
git clone https://github.com/Yonge6/onelaser-workos.git
cd onelaser-workos
python3 -m http.server 8867 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8867`。

## 可以体验的流程

1. 首页选择“任务”或“OKR”，切换演示身份体验本人或部门范围。
2. 任务列表/看板、关键词与状态筛选、新建任务、关联关键结果。
3. 员工提交成果标题、说明、可选 HTTPS 链接与标准覆盖自述。
4. 本地“演示评审”检查材料字段；显示材料缺口和未验证范围，不调用模型、不生成实际成果质量评分。
5. 负责人实际核对材料，填写 0–100 的人工质量分与意见，验收通过或退回补充。
6. 提交新版本时，旧的检查和验收结果同时失效；事件记录保留历史。
7. OKR 按业务指标的基线、当前值、目标值计算进度，与任务速度和质量分分开。
8. 查看已人审的绩效参考指标及每人样本数。没有样本显示“—”；样本门槛与覆盖率需按岗位校准；当前原型不计算综合执行分。
9. 查看钉钉登录、通讯录、通知、独立 AI 模型接口接入说明。提醒只预览草稿，不发送。
10. 导出当前可见范围的演示数据，或经确认后恢复初始样本。

## 实现与限制

- `dist/index.html`、`styles.css`、`app.js` 为无外部依赖的静态页面，支持移动端与键盘操作。
- 浏览器 `localStorage` 保存演示业务记录，键为 `onelaser-workos-demo-v4`；同一来源的浏览器共享这些演示记录。
- 切换身份仅模拟界面范围，**不是认证或安全边界**。生产版须在服务端重新实施登录、组织成员关系、角色授权与对象级数据权限。
- 当前界面范围：员工只看本人任务；负责人只看本部门任务。公司目标属于演示公开目标，个人目标按可见范围筛选。负责人不能验收本人任务；生产版需为这类任务指定上级或其他授权验收人。
- 提交内容经过 HTML 转义，成果链接只允许不含用户名/密码的 HTTPS URL。页面不读取成果链接、不上传附件。
- 当前没有数据库、真实员工登录、多人同步、文件存储、模型调用、通知发送、定时任务或企业接口连接。
- 现有 Grok Bot 的自动化接口能力未核实；Bot 和 xAI 模型 API 均未接入。任何服务端配置名称只作接入说明，不在浏览器收集密钥。
- 原型不接收真实薪资，不生成员工去留结论，不自动调整薪资。绩效指标需要负责人复核，且必须结合岗位、工作日历、依赖与批准的变更。
- 演示材料规则只看标题、文本长度与员工自述覆盖；字段齐全不等于真实成果符合标准，也不代表质量分。

## 演示口径

- KR 进度：`(当前值 - 基线) / (目标值 - 基线)`，展示值截断到 0–100%；本原型仅放置增长型指标。
- 人工成果质量 Q：当前版本已经验收任务的人工质量评分平均值。
- 按期交付 T：已经验收任务中，成果提交时间不晚于有效截止日 18:00 的比例。演示提交与事件时间使用同一个固定业务演示时钟，避免显示时间与计算依据分离。导出元信息另记录实际导出时间。
- 计划一致 P：已经验收任务中，负责人确认成果与确认范围一致的比例。
- 响应约定 R：有工作时间响应数据的已验收任务中，在 4 个工作小时内响应的比例；原型不采集真实员工响应行为。
- 待确认权重 Q 50% / T 20% / P 20% / R 10% 仅为方案草案；当前不计算个人综合执行分或跨岗位排名。

后续正式开发应按项目 `spec/` 中的服务端规则与交付方案实施，并完成真实登录、权限、文件与证据读取、审计、模型输出强校验及试点验收。

## GitHub Pages 发布

推送 `main` 分支的网页修改后，GitHub Actions 自动部署 `dist/`。也可以在 Actions 中手动运行 Deploy GitHub Pages。页面公开可访问，仅用于虚构数据的产品流程演示；真实员工系统需要独立后端、身份认证和服务端权限。
